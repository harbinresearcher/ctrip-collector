# 部署与运维方案（含更新韧性、风控处理、监控）

> 本文说明采集方式的选择、容量估算、长期运行和故障恢复。适用范围见 [采集方式与边界](../AGENTS.md#采集方式与边界)。

## 1. 交付形态

| 形态 | 用途 | 产物 |
| --- | --- | --- |
| 源码运行 | 开发与自用 | `.venv` + `python app.py --workbench --output data` |
| 现有便携打包 | 本地打包和验证中间产物 | `package_release.py` 打出的 ZIP（含 `CtripCollector.exe` 与 SHA256SUMS） |
| Windows 教师安装包 | 优先交付 | 包含工作台、可随包分发的依赖、桌面启动入口、版本清单及使用指南 |
| Android 教师安装包 | 手机直接采集的可选交付，待实现 | 手机上安装并运行，提供任务、暂停、续采与导出。平台权限由用户在手机上按系统流程授予 |
| 输出目录 | 唯一数据落点 | `data/`（数据库、CSV、报告、证据）；可整体搬走或备份 |

- 版本号 `major.minor`，每次交付打 tag；README 状态表与 ROADMAP 同步更新。
- 输出目录结构保持向后兼容：新版本必须能读旧目录（`coverage_audit` 与
  `workbench_preview` 对旧表只读，不改旧字段）。
- 回滚：保留上一个 tag 的 ZIP 与输出目录副本；数据目录不随程序回滚，只读兼容。

## 2. 备份与迁移

- `data/` 里 `*.sqlite3` 用 SQLite 在线备份（`VACUUM INTO`）而不是直接复制，
  避免拷到半个事务。
- 优先备份数据库、对象快照、采集报告和已保存媒体。可重建的导出依赖数据库和对应批次的证据仍在。
- 迁移到新机器时复制采集数据和报告，重新安装依赖。浏览器会话由使用者在新机器按平台流程建立。

## 3. 扛得住 App 更新

App 改版会让布局解析失效。现行对策分四层：

1. **拒绝未知布局**：解析器只认已验证结构；形状像但没验证过的结构必须显式
   计数（如点评图片的 `media_layout_unrecognized`），不能表现成「没有数据」。
2. **样本回归**：`tests/fixtures/` 放真实页面 dump；每次改解析先用样本跑回归，
   新增布局先补样本再改代码。
3. **失效可见**：`--audit` 的 `gap_reason` 会区分 `failed` / `unadapted` /
   `channel_capped`；App 改版后这些数字会先变，而不是静默少采。
   `channel_capped` 只表示这条通道翻到上限/末页（`capped=true`），没有同口径全部
   展示数证明采完，缺口仍计入 `reachable_missing`，并提示 `needs_other_channel`。
4. **结构指纹**：`layout_fingerprint.py` 对每类页面算稳定短哈希；手机点评任务
   （`runner.collect`）与网页点评任务（`network.collect_network`）的报告都带
   `layout: {family, fingerprint, expected, version, changed}`；与基线不一致时
   写 `layout_changed: true` 并在 `limitations` 说明，**不中断采集**（数据仍可能
   解析成功）。基线在 `tests/layout_baselines.json`，由 `tests/fixtures/` 里的真实
   样本重算；改版时样本、基线与 `FAMILIES[*].version` 一起升版本。

两类页面用的是两套**不可互换**的指纹：

- **手机点评页**（UI XML）：按先序遍历的节点序列，每个节点记
  `(深度, class, resource-id 冒号后的尾段, 是否有非空 text)`；正文和 bounds
  不参与计算，增删节点或改 class 会变，只改文字不变。
- **网页点评页**：网页是 HTML，但采集器不保留原始 HTML，只保留从 HTML 的
  `__NEXT_DATA__` 解析出的页面状态（JSON）。因此按页面状态里点评区
  （`comment_info`）的键名、层级、列表有无和标量类型取指纹，同样不算正文；
  列表按去重后的结构计算，点评条数变化不影响；没有独立点评区的页面
  （如酒店浏览器通道）退回整个页面状态。

待补：真实网页 HTML 的标签/class 指纹未做——仓库里没有真实 HTML 样本，
不拿臆造页面当基线；将来若有通道会保存原始 HTML，再补这一套。

## 4. 中断与恢复

| 场景 | 处理 |
| --- | --- |
| 响应变空 / `empty_page` | 停止无进展的续采，单独记录来源和停止原因。只有核对了末页或同口径的全部展示数，才可以确认该范围采完 |
| 网页限流、明确拒绝或验证提示 | `--drive` 保留原始状态码和对象结果，以 `reason=blocked` 停止整轮，命令行退出 1 |
| App 要求登录或人工验证 | 暂停当前任务，保留已写入的结果。用户按平台流程完成操作后，按工作台提示重新打开目标页面，或从已保存的队列继续 |
| 长时间大批量 | 每对象每轮限量（`--limit`，默认 200）+ 每轮对账，跑完就停 |
| 需要请协作者复现 | 记录公开页面入口、时间、错误类别和脱敏报告。恢复以平台允许的条件或授权为准 |

`--drive` 现在每轮只在 `missing` 严格下降时继续，`no_progress` 自动停——
这本身就是「不硬刷」的机制。命中 403/429/432/511 或验证提示时更早：整轮以
`blocked` 结束，不再进入下一轮，也不请求队列里的后续对象。

连续两次 `empty_page` / `queue_exhausted` 记为 `gap_reason=channel_capped`
（`capped=true`）：只说明这条通道翻到上限/末页，**不**因此算采完——`missing`
与 `reachable_missing` 保留真实缺口，`needs_other_channel=true` 提示去手机等
其它通道；`--drive` / `--collect-gaps` 跳过该对象避免空转。

## 5. 异常与重试

- 对超时、连接重置和普通服务暂时不可用设置退避及重试上限。重复空页、页面结构变化、登录要求和平台拒绝各自记录，保留可执行的恢复条件。
- 单对象失败不中断整轮：`rounds[].processed[]` 保留 `reason` / `error` /
  `export_error`，绝不改写成成功。
- 队列断点使用原子替换。导出失败保留原始错误与已提交的数据库记录。

## 6. 日志与监控

- 现状：`logging` 输出到控制台；每次运行落 `report-*.json`、`batch-report.json`、
  `audit-*.json`，`--audit` 的 `summary` 就是健康指标。
- 建议的运维节奏：
  1. 每次运行后跑一次 `--audit`，记录 `summary.missing` 与 `reachable_missing`；
  2. 每日比对：`missing` 应单调不增，`reachable_missing` 应为 0 或持续下降；
  3. 出现 `failed` / `unadapted` 数上升 → 视为页面或接口变化信号，先查样本。
- 每次 `--audit` 会把本次 `summary` 追加一行到输出目录的 `audit-history.jsonl`
  （`captured_at`、`missing`、`reachable_missing`、`failed/unadapted/capped` 计数；
  旧的 `source_exhausted_count` 行仍可读，按同义计入 `capped_count`），
  只追加不覆盖，写失败只记警告、不影响对账结果；输出 JSON 的 `history` 字段回读最近
  20 行并给出 `trend`（与上一次的 `missing` 差值），缺口变大时 `warning` 会写明多出多少条。

## 7. 技术选型

按业务、字段和来源建立清单。列表、详情、点评、AI 总结和媒体可各自选择来源。标明原生界面、WebView 或公开网页，记录可确认的筛选条件、对象标识、分页方式、展示总数和取得的媒体版本。登录、付费或权限要求标为来源约束。

| 任务规模 | 优先评估 | 补充路径 |
| --- | --- | --- |
| 单对象、校验新布局 | 公开页面浏览器自动化或模拟器 UI 树 | 用浏览器开发者工具观察同一正常会话加载的可见字段，用截图文字识别补充可见文本 |
| 多对象、按周期新增 | 从网页或已授权接口发现对象，只为缺少的字段打开 App；按对象维护断点与预算 | 补充其他独立可访问并允许采集的来源，将结果与来源分别留档 |
| 跨地区、持续运行 | 评估开放平台、授权数据接口或批量交付，按可见范围和公开配额估算容量 | 分城市和业务安排可恢复窗口，分开发现、详情、点评和媒体队列 |

主、备通道各自验证。平台拒绝时暂停并记录，备用通道用于填补可独立取得的字段和布局缺口。跨来源只有在主键可靠对应时才合并计数。

## 8. 容量与配置

- **先测后扩。** 按业务和来源记录去重后的新增条数、运行时长、成功率、超时率、无进展次数、页面变更和磁盘增长。比较不同队列大小、并发度和断点复用的效果。缺口总量未知时在报告里保留未知。
- **区分短测和长期预算。** 短测吞吐用来定位瓶颈。长期日容量用稳定实测的去重新增速率乘允许的执行时间，再受官方配额、任务预算和可证实缺口约束。任一关键量未知时给条件估算，写清样本、日期和假设。
- **先解决实际瓶颈。** 目录不足时补对象发现；重复率高时优化主键和缓存；等待时间高时测量加载与解析；媒体占用过大时把下载和校验独立排队；可访问范围不足时评估授权接口。
- **调度参数按业务设定。** 可配置任务预算、对象级并发、可恢复错误的重试上限和退避。同一输出目录按现有锁与事务规则写入。参数变化后用同口径对账，超出预算、长期无进展或出现平台拒绝时暂停新任务。

每条路线的评估记录包含业务与来源、实测日期和时长、对象和字段范围、可核验总量、去重新增条数、有效页数、典型和较慢的页面耗时、失败与中断次数、媒体大小、允许配额及当前缺口。日容量取「稳定新增速率 × 允许的运行时长」、已知配额可取得的条数、任务预算和已核实缺口中的最低值。无法折算时保留原配额单位和未知项。

已有实测：两个网页对象的 2 路并发将用时从 13.8 秒降到 7.6 秒，两次均各取得 5 条。该结果用于比较这个小样本的调度性能。现有配额、重试和并发的实际保证见 [验收标准和实测记录](GOAL.md)。

## 9. 最终交付与升级验收

1. 在没有 Python、项目开发工具或预配环境变量的 Windows 上双击安装，并从桌面入口打开工作台。安装程序携带代码、界面资源和可随包分发的运行组件，内置各组件版本、用途和校验值。确需外部提供的组件显示官方安装入口和复查步骤。网页和公开接口的正常使用无需手机或模拟器。
2. 手机交付需在真实 Android 上安装、打开任务并保存和导出结果，操作在手机端完成。与 Windows 版共用字段和导出口径，发布时按实际入口列出可用来源和覆盖范围。没有等效网页或授权接口的 App 字段单独标记。
3. 用一份新的输出目录走完发现、采集、导出和重新启动续跑。交付前实测同一个安装包的首次安装、升级和卸载，检查 Windows 工作台只监听本机、采集数据独立保存。用上一版的备份数据验证新版本可读，再演练回退。交付附安装包校验值和使用指南。
4. 模拟器用于开发与回归。App 升级后先核对真实页面布局、筛选与样本导出，并在手机交付前做设备验收。公开网页或 App 路径发生变化时，给该来源标注受影响字段，并记录已验证的备用来源。第三方客户端的保护变化属于兼容性信号，恢复依据平台的正常访问条件。
5. 用可控的本地故障测试分别核验超时后的退避、持续错误的熔断、限流或验证提示后的停止，以及中断后续跑。监控按来源和业务分开统计采集成功率、每小时去重新增、超时、连续失败、拒绝和磁盘占用。发布记录列出触发条件、日志或报告位置、恢复结果及尚未实测的场景。
