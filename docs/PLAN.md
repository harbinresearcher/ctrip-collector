# 携程点评采集实施计划

## 0.4 酒店浏览器响应通道

沿用用户已授权的正常登录。酒店使用本机专用 Edge 配置目录，正常网页翻页触发请求，程序仅监听当前酒店的点评响应；不保存认证请求。首批结构化状态同时保存 AI 总结，公开酒店详情补充地址、设施、政策。AI 优选图集未返回，不冒充完整。

1. 对象 ID、响应结构、默认筛选条件和连续页码校验；未知响应不能当空页。验证：错误酒店、合法空酒店、取消均有回归。
2. 共用 SQLite 去重和导出；GUI 与 CLI 按酒店链接选择浏览器通道。验证：真实 EXE 连续分页、重复运行零新增、CSV/JSONL/SQLite 一致。
3. 独立构建 0.4，保留旧版；检查 ZIP 哈希、解压后启动与源码测试。用户登录状态不进交付目录。

全站发现、其他点评类型、AI 优选图集仍未完成；不将测试通过表述为全委托完成。

## 0.3 城市景点目录

增加有界城市景点发现，沿已验证的列表页路由翻页；使用正式列表卡片，不混入页脚推荐。验证返回地区与页码、过滤邻城、业务 ID 去重，输出 JSON 审计清单及一行一个链接的 TXT。GUI 可生成后转入网络模式，CLI 支持发现后串接采集。不是全站枚举器，餐饮、购物、酒店目录仍未适配。真实验证：抚松两页 19 本地对象、排除 1 邻城；串接两个对象各 3 条评论。23 回归通过。

## 0.2 当前范围与验收

用户确认先覆盖点评对象及完整字段，不含游记、笔记和票价库存。本次先实现已核验的景点、餐饮、购物网络分页及酒店 AI 手机补采。独立保存来源、计数差异和未取得字段，不把测试版当全站成品。

1. 根据公开页面确认业务 ID 和资源类型；请求详情与点评接口，稳定 ID 去重落库，JSONL 保留公开嵌套字段。验证：真实景点达到 500 条，复跑无重复新增，末页 null 与拦截响应区分。
2. 酒店 AI 总结用真机展开，独立保存段落、关联计数、原始 XML 和人工声明身份。验证：三段实际文本及收起边界；取消后不点击；图片集合标为未采集。
3. 窗口增加网络多链接、手机评论、酒店 AI 三种模式；构建 0.2 独立交付目录，21 项回归、EXE 实测及 ZIP 校验。

未完成：酒店高速分页、全站目录、其他点评对象类型、AI 优选图集、跨屏 AI 全文、全来源字段完整性。旧 0.1 文档以下留作历史。

目标：交付可独立运行的 Windows 单对象评论采集器，并保留真实测试证据。全站目录发现、图片原文件下载和全量覆盖不属于此测试版已完成功能，仍是整体委托的未完成部分。

架构：ADB 读取 Android UI XML，按评论卡片解析，SQLite 持久保存，CSV 导出，Tkinter 操作窗口。原始 XML 留作核对。日期类型区分入住月份和发布日期。无稳定评论 ID，去重键使用对象、用户名、日期和正文；这不是可靠的服务端 ID。

1. 写真实 XML 回归测试，验证酒店/景点、短评论、不截断长评论、商家回复排除、重复保存、对象隔离和 CSV 公式转义。先保留失败记录，再实现解析与存储。
2. 实现 ADB 检查、唯一临时文件、超时、当前包校验、有限滑动、停止、折叠标记、原始证据和运行报告；模拟设备异常并真机跑连续采集。
3. 实现 Windows 操作窗口，用 PyInstaller 打包；附本次从 Google 官方获取的 ADB 37.0.1 及原始 NOTICE，优先识别同目录 platform-tools。核验 EXE 自检和真实采集，说明版本和边界。

验收：自动测试通过；真实连续采集数量以数据库为准；达到 500 条前不得声称 500 条验收通过；长时间无新增不是证明全量结束。中断后重新从评论页开始会去重，不能声称能恢复到精确滚动位置。
