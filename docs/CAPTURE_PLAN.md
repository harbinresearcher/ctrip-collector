# 0.5 App 点评响应接入

沿用已授权的点评对象与完整字段范围，保留现有 SQLite 和 0.4 浏览器通道。新工具用于补足 App 来源，不迁移其他工程、不引入第二套主库。

选择：先测试普通代理与真实 App 返回；浏览器继续负责已打通字段。UI 用于打开目标页及对账。此次不升级到 root、重打包或证书固定绕过。

1. 新增受限响应 addon：仅信任携程域名边界；未知接口只记服务名称和状态，不写 URL 查询、请求头、请求正文、账号响应。已验证酒店点评接口按酒店 ID 校验、清理后保存完整 JSON。先用伪造域名、认证字段、错误对象、压缩响应做回归。
2. 在本机回环监听，通过 ADB reverse 连接手机；读取并在 finally 恢复原代理。真实 App 小样判断 TLS 是否可用，不把握手失败归咎于证书固定。失败则保持浏览器采集可用并记录限制。
3. 采集程序增加响应文件导入，按对象分组、稳定 ID 去重、原有 CSV/JSONL/SQLite 输出。保留来源和分页覆盖，不把抓到若干响应称为全量。
4. 尝试打开 AI 优选晒图，识别其正常响应或页面结构。只有获得真实证据才标为已采集。打包新版本并验证源码回归、EXE 导入和数据一致性。

暂不改变 D:/mydata/myproject/ctrip-app-capture 原骨架；使用该工程的环境与已安装工具，避免修改其他会话维护的源文件。
