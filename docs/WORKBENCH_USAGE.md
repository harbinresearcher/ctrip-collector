# Windows 本地工作台

在仓库目录安装 `requirements.txt` 中的依赖后运行 `python app.py --workbench --output data`。工作台默认在 `http://127.0.0.1:8765` 提供服务。使用 `--port` 可以选择其他端口。

## 网页和本地文件

- 「对象点评」接收携程详情链接。设置目标条数后开始，任务结果显示实际保存数和停止原因。
- 「景点、餐饮与购物公开资料」读取可见的对象资料和页面提供的样本。可在结果中将对象填入单独的点评任务。
- 「自动发现地区和点评对象」按所设地区和对象数生成队列。「继续地区目录」可选择以前的任务报告。
- 「检查本地字段覆盖」读取当前输出目录，可查看网页及 App 点评、已保存的详情和图集。收集结果及浏览器的独立资料保存在输出目录。
- 「保存报告」保存本次任务的 JSON。点评 CSV、图集 ZIP 和报告有各自的下载入口。

## 在模拟器采集 App

在 Windows 上启动 Android 模拟器并打开携程。`adb devices` 可以查看设备编号。

```powershell
python app.py --workbench --output data --adb adb --adb-serial emulator-5554
```

工作台显示「携程在前台」后，按采集方式打开对应页面。列表任务填写 App 顶部显示的城市。详情和点评以页面显示的名称为准。点评的数字 ID 用于本地分组，报告记录编号来源和页面核对状态。

- 酒店列表和详情分别输出搜索条件与已读到的房型卡片。
- 餐厅和购物列表结果可填入详情任务，随后可从详情填入点评任务。
- 「手机评论」和「餐厅点评图集」可按名称或编号搜索本地目录。选中对象会填入名称和编号，并显示对应的本地证据文件。请在模拟器打开该对象的点评页。工作台会核对页面名称，并把编号来源写进报告。需要手填时，点击「清除选择」。
- 选择本地景点后，可勾选「自动打开景点点评」。在模拟器停留在携程首页或该景点的点评页，再开始采集。首页自动搜索需先有一份带完整地址的景点详情快照。当前页面或地址无法核对时，工作台会提示手动打开。批次样本可在「检查本地字段覆盖」中按任务恢复。
- 「景点点评队列」可以按顺序加入 1 至 20 个已保存完整地址的景点。将模拟器停在携程首页，设置每个景点的本地累计条数和滚动上限，再开始。工作台会核对地址、逐个打开点评，并在每个景点结束后保存队列位置、停止原因和可下载的样本。
- 点击「读取 App 补采建议」时，工作台从本地记录预选有完整地址的景点。检查名单和每个景点的计划补采条数后开始。程序用 App 已采量计算逐项累计目标，遇到同口径的已知缺口时缩小目标。最后一屏按实际读到的点评保存。总量未知的景点会保留未知。
- 新建队列时可勾选「同时保存景点 AI 总结」。工作台会尝试展开总结，并在每项结果里显示实际保存的段数、预览或展开状态。可以在队列结果或历史队列中下载同一批总结的 JSON。导出同时列出没有保存成功的项目。
- 要继续队列，请在同一输出目录启动工作台，在模拟器打开携程首页，再选择已保存的队列。已留档的景点会跳过。页面停滞和达到滚动上限也会保存本轮结果，采集范围可在队列中逐项查看。
- 在「手机评论」选择餐厅，勾选「保存点评图片」。让点评标题、日期、正文和图片卡片同时可见，再开始读取。结果可下载图片裁图 ZIP 和本次点评 CSV，ZIP 清单用行号关联 CSV。部分三列卡片会标注图片总数，工作台单独记录这个数，并跳过被徽标遮挡的格子。
- 「餐厅点评图集」从图片完整可见的点评卡片进入。选好餐厅或手填名称和对象 ID，再设定页数上限。程序选择当前屏第一条可核对的带图点评，调用 App 下载，并提供图集 ZIP 和对应点评 CSV。图片为 App 保存的版本，画质与尺寸以 App 提供的文件为准。
- 在「餐厅当前详情」勾选「读取完整推荐菜清单」。让名称和推荐菜卡片同时可见，并把卡片滑到最左边。浮层遮住「查看全部」时，可把页面稍往上滑，露出该入口。报告会列出已读菜名、页面展示总数及停止原因。
- 景点 AI 总结需在「用户点评」显示总结卡。看得到「查看全部总结」时，工作台会尝试展开。
- 景点 AI 图集从同一景点「用户点评」的晒图入口进入，保存 App 显示的主图裁图。继续采集时，从「图集起点」选上次批次，并在模拟器停到上次保存的最后一张大图。页面、页码和图片核对后会接上下一张。
- 「App 页面字段自选」可以填写要读取的可见标签。「读取 App 截图文字」在 Windows 上识别所选图片区域。

「停止并保存」会请求结束当前采集，并保留任务已写入的记录。每次任务的实际覆盖范围以结果中的条数、页码、字段和停止原因为准。
